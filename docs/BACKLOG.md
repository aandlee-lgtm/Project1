# PhotoSelect feature backlog

Feedback from testing is recorded here as product features. Nothing in this list is built,
versioned or released until the owner's message includes **build_new**; then the open items are
implemented, tested and shipped together as one new version.

| # | Requested | Feature | Status |
|---|---|---|---|
| 1 | 2026-10-09 | **Bursts defined by visual likeness as well as timing.** Compute a "% likeness" between frames (0–100 %, from how alike the images look) and use it explicitly in burst grouping: frames belong to the same burst when they are close in time **and** at least N % alike. Show the % to the user: a "Similarity ≥ N %" slider replacing the current tolerance number, each frame's likeness to the burst's top frame in the burst comparison and viewer, and a burst's average likeness in the diagnostic report and CSV. | Done in 1.3.0 |
| 2 | 2026-10-09 | **Near-identical shots a few seconds apart count as a burst.** Extend item 1: frames that are very alike (a higher "near-identical" likeness, e.g. ≥ 90 %, adjustable) are grouped even when they are several seconds apart (adjustable window, default about 10 s), not only within the normal burst gap. The burst view marks such frames as near-identical. | Done in 1.3.0 |
| 3 | 2026-10-09 | **Status line without the decoder version.** Remove "· LibRaw 0.22.1" from the status line after a scan; keep everything else (photos analysed, time, cache, camera previews, bursts / single frames, could not be analysed). The decoder version stays available in Help → About and the diagnostic report. | Done in 1.3.0 |
| 4 | 2026-10-09 | **Brighter teal accent colour.** The current accent (`#ade1c5`, a pale teal that reads almost lime green) becomes a slightly brighter, clearer teal, staying in the teal family. The related shades change with it: score bars, badge borders, pill backgrounds and the text on primary buttons. Text must stay easy to read on the dark panels. | Done in 1.3.0 |
| 5 | 2026-10-09 | **Learn from my decisions (on this Mac, with my approval).** Once enough photos have been marked by hand (about 30 or more Keep / Consider / Drop decisions and likes), PhotoSelect suggests the slider weights (sharpness, subject focus, composition, exposure) and Keep / Consider thresholds that best match those decisions. It shows the proposed change and why, for example "you keep frames with high subject focus even when composition is low", with how many of your past decisions it would have matched before and after. Nothing changes until I click Apply, and I can undo it. Learned settings can be saved per folder or as named profiles for kinds of shoot (e.g. sailing, portraits). Everything stays on the Mac: no upload and no hidden model, and the reasons shown for each photo stay a complete explanation. | Done in 1.3.0 |
| 6 | 2026-10-09 | **Send selections to Adobe Lightroom Classic (plug-in, star ratings).** Workflow: cull in PhotoSelect *before* importing. PhotoSelect saves a selections file (not in the photo folders); after importing the folder, one click in Lightroom (Library → Plug-in Extras → Apply PhotoSelect Selections) applies it. Mapping: **Keep → 3★, Consider → 2★, Drop → 1★, ♥ Like → 5★**; your own decision wins over the suggestion, and photos with neither are left alone. Keywords are added too (PhotoSelect › Keep / Consider / Drop / Liked / Burst NN / Camera preview), so Smart Collections can be built. Photos are matched by original file name plus capture time, so it still works when Lightroom copies or renames files on import. Before applying, it shows a summary (matched, not found, would change existing stars) and does not overwrite stars already set in Lightroom unless asked. The plug-in is bundled in the app and installed via Help → Install Lightroom Plug-in…. No XMP sidecars, so nothing is written into photo folders. | Done in 1.3.0 |
| 7 | 2026-10-09 | **Shorter photo cards for camera-preview photos.** To save space, remove the sentence "Scored from the embedded camera JPEG (camera sharpening and noise reduction included), not the RAW pixels." from the photo cards in the grid. The card shows its normal reason line instead (the suggestion and its burst result), like every other photo. The **CAMERA PREVIEW** badge on the thumbnail and the source line under the file name remain. The full explanation stays in the photo viewer, the CSV and the diagnostic report. | Done in 1.3.0 |
| 8 | 2026-10-09 | **Nikon Z50 II (and other) High Efficiency NEFs fall back to the camera preview.** The owner's DSC_1312.NEF (Nikon Z50 II, High Efficiency NEF) is reported as "the RAW data is damaged or truncated (Data error or unsupported file format)" and not analysed. Cause: for this camera, LibRaw 0.22.1 starts decoding the HE (intoPIX TicoRAW) data and stops with a *data error*, instead of the *unsupported* error it gives for Z6III HE files, so the 1.1 fallback is never tried. Fix: when a NEF contains the High Efficiency marker, treat a data error like an unsupported one. The file is then analysed from its full-size embedded JPEG (5568 × 3712 here) and labelled CAMERA PREVIEW. Genuinely damaged files without the marker still never fall back. Add this file's behaviour as a regression test, and add a Z50 II HE sample to the macOS acceptance run if one is available. | Planned |
| 9 | 2026-10-09 | **Sony A7 and A9 series ARW verified and supported.** PhotoSelect already accepts .ARW, but no Sony file has been tested. Make sure every body in both series works: A7, A7 II, III, IV, V; A7R, R II, R III/IIIA, R IV/IVA, R V; A7S, S II, S III; A7C, C II, CR; A9, A9 II, A9 III (ILCE-7…, ILCE-9…). Cover each RAW mode: uncompressed, compressed, and lossless compressed (L/M/S on newer bodies). (1) Fetch every A7/A9 sample from raw.pixls.us and check each one decodes with the bundled LibRaw: correct size, orientation, and agreement with Apple's own RAW render. Add the Sony files to the macOS acceptance run and list each model and mode with its result in the validation report. (2) Any body or mode the bundled LibRaw cannot decode: update rawpy/LibRaw if a newer release supports it. Otherwise use the camera-preview fallback with the CAMERA PREVIEW label, as for Nikon HE. Note that Sony's embedded JPEG is often only about 1616 × 1080, which is less useful for judging focus, and say so per model. (3) Check that Sony capture times, including sub-seconds where recorded, group bursts correctly, including A9 high-speed bursts. Add a *Sony ARW* option to the file-format filter, and mention Sony in the interface and README. (4) Models without a public sample are listed as NOT TESTED, never claimed as working. | Planned |
| 10 | 2026-10-09 | **Send to Lightroom gives clear feedback and guides installation.** The owner reported that "Send to Lightroom does not seem to do anything" and asked where and how to install the plug-in. In 1.3.0 the only feedback is one line of small text under the progress bar, and installing is a separate Help menu item. Planned: clicking Send to Lightroom opens a dialog. It shows how many photos were sent and their stars, whether the plug-in is installed (with an **Install plug-in** button if not), and the next steps in Lightroom with a reminder to restart Lightroom after installing. A **Show plug-in in Finder** button supports the manual route (Lightroom → File → Plug-in Manager → Add). Errors appear in the same dialog. | Planned |
